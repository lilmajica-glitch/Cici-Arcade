# 2026-10-02 · 数学专注律动配乐工作留痕

日期采用 America/Los_Angeles。基线提交：`71f3460`（Cici MVP）。用户需求：仔细研究 7–12 岁儿童数学练习的音乐，增强节奏与音乐质感，提供先行试听，接入当前版本，并保留工作证据。

本轮完成原创 Web Audio 配乐《向前一点》、54 秒试听、独立背景音乐音量、生产版本接入，以及研究、代码、真实音频渲染和浏览器验收记录。适龄是设计目标；没有用工程测试替代真实儿童的专注或心流实验。

## 研究与决策

原始论文的对象、任务、发现、证据边界和每项作曲推论见 [研究记录](./focus-music-research.md)。检索包括儿童数学、儿童知识保留、器乐/歌词对认知任务的影响与口算心流；核对了 2026 年儿童研究，没有混用音乐训练与背景音乐效果。

据此采取无歌词、适度刺激、稀疏旋律、可自行降低音量的方向。108 BPM、54:46 摇摆与电子 funk 配器均是本次作曲选择，不是论文证明的“儿童最佳参数”。

工作顺序：查阅研究与现有音频架构 → 编写共享乐谱及合成音色 → 提供试听页 → 接入游戏与生产入口 → 导出试听 WAV → 验证整曲、音效与真实操作 → 保存文档、JSON 与截图。试听在当前工作过程中已提供给用户；没有把试听是否受喜欢当成效果验证。

## 实现变更

| 文件或模块 | 最终行为 |
| --- | --- |
| `src/audio/score.ts`、`arrangement.ts` | 原创八小节和声、十六小节乐句；切分鼓/贝斯，微摇摆，稀疏五声音阶旋律；纯乐谱函数供实时与离线共同使用 |
| `Synth.ts` | 紧致底鼓、带力度的军鼓/踩镲、可在小扬声器听见谐波的贝斯、FM 电钢琴、辅助打击乐；鼓/低音/电钢琴保留音体再释音；噪声用固定种子 |
| `Mixer.ts` | 电钢琴低音量单次空间反射；独立背景音乐音量；35ms 全局静音与 50ms 音乐渐变最终精确到零 |
| `MusicEngine.ts`、`Sequencer.ts`、`progression.ts` | 固定 108 BPM；开局四个基础声部；六阶段在下一小节边界加入配器；最后一题保持从容，不再播放 riser |
| `AudioEngine.ts`、`preferencesStore.ts`、`useAudioLifecycle.ts` | 默认背景音乐 75%；初始化时应用音量与静音偏好；已有手势解锁、页面隐藏暂停和资源销毁路径保留 |
| `MusicVolume.tsx`、`App.tsx`、菜单及音乐指示 | 背景音乐可单独调到零，仍保留答题音效；菜单提供试听链接；显示对应配器阶段；音量偏好在内存中管理 |
| `music-preview.html`、`src/preview/`、`src/audio/preview.ts` | 54 秒六阶段试听、重播/停止/音量、PCM16 WAV 导出；点击后才创建实时音频；隐藏/离开页面停止试听 |
| `vite.config.ts` | 游戏和试听两个生产入口；试听不依赖开发服务器模块 |
| 自动与浏览器音频测试 | 维护进度与调度回归测试；增加作曲约束、小节切换、固定噪声和 WAV 格式检查；整曲渲染覆盖六阶段与混音 |

离线渲染会预先排入整首曲子的未来音符，原来的 96 源实时上限会误杀这些未来音符。本轮区分 OfflineAudioContext 与实时场景：实时仍有 96 源上限，离线试听以固定 54 秒限制规模。这一修复由六阶段的后段音量窗口和完整试听共同验证。

React 检查遵循独立状态订阅、简短派生值与分离音频调度；试听页使用独立入口，游戏没有加载 WAV 编码或离线试听模块，节拍没有加入 React 每帧状态。

## 浏览器验收

使用 Browser 技能与 frontend-testing-debugging 流程，浏览器为 Codex 内置 Chromium，无替代浏览器。验证流程：菜单 → 音乐音量/静音 → 开始 → 错误重试 → 20 次正确 → Victory → 重玩；生产构建另验开始、一道题、菜单试听导航与播放。

| 要求 | 结果 |
| --- | --- |
| 页面身份 | 开发 `http://localhost:5173/`、生产 `http://localhost:4173/` 和生产 `/music-preview.html` 的 URL、标题与内容正确 |
| 非空白、无框架覆盖层 | 游戏、试听与检查入口均呈现实际内容，无 Vite 错误覆盖层 |
| 控制台 | 所检查开发游戏、基础音频入口、整曲入口与生产页面的 warn/error 为空 |
| 截图证据 | 桌面、手机游戏、手机胜利及桌面/手机试听，见下方图库 |
| 真实交互 | 通过 UI 数字键完成 20 题；依据页面题目计算，没有注入答案、调用内部游戏状态或跳过进度 |

具体结果：

- 默认桌面视口 1280×720；游戏页面可用内容宽度 1265px。手机模拟视口 390×844，游戏无横向溢出，数字键盘底边约 732px。
- 背景音乐 slider 的 Home 变为 0，辅助文本明确“背景音乐关闭，保留答题音效”；End/左方向键能调节到 95%。它没有触发数学输入。
- 首次开始后 `data-audio-state=ready`。第一题故意提交 99：HP 100、进度 0，允许立即重试。全局静音/恢复按钮的状态正确。
- UI 连续完成 20 题，HP 每题减少 5；第 12、15、17 次正确后分别显示阶段 4、5、6。最后 HP 0，Victory 一次答对 95%、最大连击 ×20；重玩恢复 HP 100、音频 ready。
- 生产游戏首次手势解锁成功；真实作答后 HP 95。重新进入菜单，点击试听链接导航至生产 `music-preview.html`。
- 生产试听完成整段 54 秒并自动结束；重播可启动，停止显示“已停止”；试听音量实际可调。手机试听无横向溢出，内容允许正常纵向滚动（可用内容宽度因桌面滚动条为 375px）。视口覆盖已恢复默认。
- 试听 WAV 由真实 OfflineAudioContext 导出。本轮内置浏览器的下载事件等待未返回；因此读取页面的 WAV 下载链接并将同一字节流保存到本地，没有换用另一套音频生成器。
